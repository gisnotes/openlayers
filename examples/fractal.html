This example demonstrates how features with many vertices can be efficiently rendered.

本示例演示 OpenLayers 矢量图层在面对包含成千上万个连续顶点（海量高密度几何折线）时的极限渲染性能。通过基于链表数据结构的科赫雪花（Koch Snowflake）分形算法，滑动表单调节递归深度（0~9 级），可动态生成高达数十万个顶点的复杂分形几何，并展示防抖更新与流畅缩放机制。

--- ### 📚 学习记录与技术深度解读 (Learning Notes) #### 1. 核心架构与设计思想 (Core Architecture & Design) - **科赫雪花（Koch Snowflake）分形几何模型**： 从一个等边三角形开始，在每一轮迭代中，将多边形的每条边三等分，并在中间的三分之一线段上向外搭建一个新的等边三角形，同时抹去底边（即形成 `_/\_` 形状）。 - 递归深度 $d=0$ 时，点数为 4； - 递归深度每加 1，线段数量翻 4 倍（$4 \times 4^d$）； - 当深度达到 8~9 级时，顶点数达到数十万量级，是检验 WebGIS 引擎几何遍历和 Canvas 绘制性能的黄金标尺。 - **单向链表（Linked List）在分形插值中的优势**： 在频繁执行中段插入操作时，如果使用原生 JavaScript 动态数组（`Array.splice`），由于会导致后续所有元素在内存中整体后移，时间复杂度为 $O(N^2)$，在深度达到 6 级时便会导致页面崩溃。本示例采用单向链表结构（`coordsToGraph`），插入新节点的时间复杂度仅为 $O(1)$，遍历一次耗时 $O(N)$，极大加速了分形生成速度。 #### 2. 源码与关键 API 剖析 (Source Code & API Analysis) - `injectNodes(startNode)` 极坐标几何生成： 计算两点间向量差 `[dx, dy]`，在 $1/3$ 和 $2/3$ 处分别计算插入点，中间突起的顶点通过旋转角 $\theta + \pi/6$ 与斜边长 $r = \frac{\sqrt{dx^2+dy^2}}{2\cos(30^\circ)}$ 精准推导。 - `geometry.setCoordinates(coordinates)`： 几何对象通过 `setCoordinates` 就地更新扁平坐标数组，触发底层包围盒（Extent）重新计算与 R-Tree 索引刷新，通知视图图层重绘。 - **200ms 防抖更新机制（Debouncing）**： 在 `depthInput.onchange` 中维护 `updateTimer`，在连续拖动滑块时取消前置定时器，仅在停顿 200ms 后才触发重量级计算，防止频繁阻塞浏览器主线程。 #### 3. 生产实践踩坑与性能调优 (Production Pitfalls & Optimization) - **超高密度线段的 Canvas 描边性能瓶颈**： 当顶点数量超过 10 万时，Canvas 原生 `ctx.stroke()` 会消耗大量 GPU/CPU 光栅化时间。生产中对于高密度折线，可采用 WebGL 矢量渲染器（`WebGLVectorLayer`）或在视口缩放时结合拓扑抽稀（Simplify）。 tags: "fractal, vector" ---
