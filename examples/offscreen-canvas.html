The map in this example is rendered in a web worker, using OffscreenCanvas.

在此示例中，完整的矢量瓦片地图在 Web Worker 后台子线程中渲染，依托浏览器的 OffscreenCanvas（离屏画布）与 ImageBitmap 零拷贝转移技术，彻底将复杂的矢量反序列化、样式计算与栅格化脱离主线程。

📚 学习记录与技术深度解读

1. 核心架构与设计思想

  • 主线程 UI 与渲染管线彻底解耦： 在传统前端单线程架构中，Mapbox 矢量瓦片（MVT PBF）的反序列化、几何构建、文字排版与样式匹配会密集抢占主线程 CPU 时间片，极易引发页面滚动卡顿或输入响应延迟。通过 OffscreenCanvas 与独立 Web Worker，所有繁重的几何构建与绘制指令均在子线程独立核中执行，主线程仅负责手势监听与最终图像合成。
  • 异步视图状态双向同步与仿射矩阵补偿： 由于主线程手势交互（平移/缩放）具有极高的时效性，而 Worker 异步渲染返回存在微小延迟，为了避免地图在快速拖拽时出现闪烁或画面跳动，主线程维护了一个 updateContainerTransform() 几何补偿矩阵，通过 CSS transform 实时将 Worker 上一次渲染的旧帧变换到主线程最新的瞬时中心点与缩放尺度，实现丝滑流畅的交互体验。
  • 跨线程要素拾取通道（Cross-Thread Hit Detection）： Worker 内部持有完整的空间索引与矢量要素，主线程捕获 pointermove 像素坐标后，通过 postMessage({ action: 'requestFeatures', pixel }) 将像素坐标分发给 Worker，Worker 拾取要素属性后回传，实现主线程信息窗的高效响应。

2. 源码与关键 API 剖析

  • new Worker(new URL('./offscreen-canvas.worker.js', import.meta.url), { type: 'module' })：使用现代 ES 模块化语法实例化 Web Worker，支持在 Worker 内部使用标准的 import 导入 OpenLayers 核心包。
  • createImageBitmap(image) 与 Transferable 零拷贝传输：主线程解析出的雪碧图纹理在传递给 Worker 时，利用 Transferable 对象列表 [imageBitmap] 将底层显存所有权直接转移给子线程，避免了数兆字节内存的大开销结构化克隆。
  • layer.getRenderer().useContainer = ...：Worker 内部模拟了一个轻量级的无头 DOM 容器，重写图层渲染器的容器注入逻辑，直接将绘图输出定向到 OffscreenCanvas 上下文。
  • frameState.animate = true：若主线程发生缩放平移而 Worker 渲染尚未完成，强制标记渲染循环保持活跃，直至新帧送达。

3. 生产实践踩坑与性能调优

  • 浏览器兼容性与安全上下文： OffscreenCanvas 与现代 Web Worker 必须在安全上下文（HTTPS 或 localhost）中运行。对于老旧浏览器（如 iOS Safari < 16.4 或部分安卓 WebView），需提供回退到主线程常规 Canvas 渲染的降级容灾方案。
  • Worker 内部文本字体测量（Text Metrics）： 在 Web Worker 中无法访问标准的 document.fonts，若使用带有文本注记的矢量瓦片，需要使用本地系统通用字体（如 getFont() 替换为 serif / sans-serif）或借助 Canvas 2D 的 ctx.measureText() 进行降级排版。
  • 内存泄漏与并发并发丢帧（Frame Dropping）： 用户高速滚轮缩放时，主线程可能在 1 秒内产生 60 次视图变化。若不加以节流或设置丢帧锁（if (!rendering)），Worker 消息队列积压会导致高延迟和内存膨胀。本示例严格采用互斥锁与 requestAnimationFrame 协同，确保每一时刻仅有一帧在 Worker 中处理。
