Custom Canvas Tiles / 自定义 Canvas 切片与 TMS 坐标网格

layers2 vectortiles6 tms1 canvas7

Renders tiles with TMS coordinates for debugging. / 渲染带有 TMS 切片坐标的网格以进行空间调试与切片对齐验证。

The black grid tiles are generated on the client with an HTML5 canvas. The displayed TMS tile coordinates are produced using a custom template for TMS, the vector tile source's 512 pixel tile grid and the zDirection setting for vector tiles. Notice how the country polygons can be split between tiles and vector labels may appear in each tile.

黑色网格切片由客户端借助 HTML5 Canvas 动态即时生成。 所显示的 TMS 切片坐标系利用了自定义 TMS 模板（如 {-y}）、矢量切片源的 512 像素切片网格（TileGrid）以及矢量切片专用的 zDirection 设置。 请观察多边形国家要素是如何被切片边界无缝截断分割的，以及矢量文本标注是如何在各个切片中独立渲染的。

📚 学习记录与技术深度解读 (Learning Notes)

1. 核心架构与设计思想 (Core Architecture & Design)

  • TMS（Tile Map Service）与 XYZ 坐标系的 Y 轴倒置原理：
    • 标准 XYZ / WMTS：原点位于左上角（Top-Left），随着纬度降低，Y 坐标自顶向下递增（$Y = 0$ 在最北端 85.05°N）。
    • TMS 规范：原点位于左下角（Bottom-Left），符合传统笛卡尔直角坐标系，$Y = 0$ 在最南端，随着纬度升高，Y 坐标自底向上递增。
    • OpenLayers 在 URL 模板中通过 {-y} 占位符支持 TMS 协议，公式为：{-y} = (1 << z) - 1 - y。
  • TileDebug 调试切片源在空间排错中的价值： ol/source/TileDebug 可以在客户端透明生成一个轻量级的动态调试网格，将当前的缩放层级（Z）、列号（X）、行号（Y / -Y）直接绘制在对应的切片网格中心。它是排查切片 404、切片漂移、跨瓦片接缝不齐的核心排错武器。

2. 源码与关键 API 剖析 (Source Code & API Analysis)

  • TileDebug({ template: 'z:{z} x:{x} y:{-y}', projection, tileGrid, zDirection: 1 })：
    • template：支持自定义调试文本模板，使用 {-y} 可精准反映 TMS 规范下发给服务端的实际请求行号。
    • tileGrid：直接绑定矢量切片图层数据源的 getTileGrid()，确保调试网格与真实的矢量切片物理分块完全重合。
    • zDirection: 1：控制缩放过程中的切片选择偏向。1 表示倾向于选择更高分辨率（更大 Z 级别）的瓦片进行插值显示，提升清晰度。
  • 多边形跨切片分割与标注重复机制： 由于矢量切片服务器在切割几何时，会在各瓦片边界进行裁剪并将国家属性写入每个相关切片。若不启用 declutter: true（标注避让整理），同一个国家的名称可能会在相邻的多个切片中反复出现。开启 declutter: true 后，OpenLayers 的全局避让管理器会在视口中执行多边形标注去重与最优摆放。

3. 生产实践踩坑与性能调优 (Production Pitfalls & Optimization)

  • TMS 坐标翻转导致的切片 404 灾难： 在接入基于 GeoServer GWC、MapProxy 等支持 TMS 协议的服务时，若切片 URL 误写成了 {z}/{x}/{y}.pbf 而非 {z}/{x}/{-y}.pbf，会导致请求发送到地球对称的另一侧半球，返回大面积 404 或南美与北美颠倒。使用 TileDebug 能够一目了然验证 Y 轴计算是否正确。
  • TileDebug 生产环境剔除： TileDebug 仅供开发调试时使用，每个瓦片都会创建 Canvas 上下文并执行 fillText，生产上线前应通过环境变量或配置开关彻底移除该图层，释放 CPU 与 GPU 资源。
main.js 
import Map from 'ol/Map.js';
import View from 'ol/View.js';
import MVT from 'ol/format/MVT.js';
import TileLayer from 'ol/layer/Tile.js';
import VectorTileLayer from 'ol/layer/VectorTile.js';
import TileDebug from 'ol/source/TileDebug.js';
import VectorTileSource from 'ol/source/VectorTile.js';
import Fill from 'ol/style/Fill.js';
import Stroke from 'ol/style/Stroke.js';
import Style from 'ol/style/Style.js';
import Text from 'ol/style/Text.js';

// Base styling for country polygon boundary and label text
// 国家多边形边界与文本标注的基础样式
const style = new Style({
  fill: new Fill({
    color: 'rgba(255, 255, 255, 0.6)',
  }),
  stroke: new Stroke({
    color: '#319FD3',
    width: 1,
  }),
  text: new Text({
    font: '12px Calibri,sans-serif',
    fill: new Fill({
      color: '#000',
    }),
    stroke: new Stroke({
      color: '#fff',
      width: 3,
    }),
  }),
});

// Vector tile layer consuming TMS-indexed MVT tiles from GeoServer GWC
// 矢量切片图层，消费来自 GeoServer GWC 的 TMS 坐标规范 MVT 矢量切片
const vtLayer = new VectorTileLayer({
  declutter: true,
  source: new VectorTileSource({
    maxZoom: 15,
    format: new MVT(),
    url:
      'https://ahocevar.com/geoserver/gwc/service/tms/1.0.0/' +
      'ne:ne_10m_admin_0_countries@EPSG%3A900913@pbf/{z}/{x}/{-y}.pbf',
  }),
  style: function (feature) {
    style.getText().setText(feature.get('name'));
    return style;
  },
});

// Debug layer rendering client-side canvas grid with TMS coordinates
// 调试图层，使用客户端 Canvas 实时绘制包含 TMS 坐标编号的网格
const debugLayer = new TileLayer({
  source: new TileDebug({
    template: 'z:{z} x:{x} y:{-y}',
    projection: vtLayer.getSource().getProjection(),
    tileGrid: vtLayer.getSource().getTileGrid(),
    zDirection: 1,
  }),
});

// Initialize map with vector tile layer and debug overlay
// 初始化包含矢量切片与调试覆盖网格的地图实例
const map = new Map({
  layers: [vtLayer, debugLayer],
  target: 'map',
  view: new View({
    center: [0, 6000000],
    zoom: 4,
  }),
});
