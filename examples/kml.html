This example uses the ol/format/KML to parse KML for rendering with a vector source.

此示例演示了如何使用 ol/format/KML 解析器加载并渲染 Google Earth 标准的 KML（Keyhole 标记语言）矢量文件。 将鼠标悬停在地图上的要素上时，通过 map.forEachFeatureAtPixel() 像素拾取算法，可在下方实时展示对应要素的名称属性（name）。

📚 学习记录与技术深度解读

1. 核心架构与设计思想

  • KML (Keyhole Markup Language) 协议与解析管线： KML 是一种基于 XML 语法的 OGC 开放地理标记语言，广泛应用于 Google Earth 与航拍无人机航线规划。 ol/format/KML 内部集成了标准 DOMParser，能够高效解析 <Placemark>、<LineString>、<Polygon> 等空间节点，并支持自动抽取 KML 内嵌的色彩描边样式（<Style> 与 <StyleMap>）。
  • 地理坐标到投影平面的透明映射： 依据 OGC 规范，KML 文件内部的坐标必须且只能是 WGS84 经纬度（EPSG:4326）。 当在 VectorSource 中注入 new KML() 时，OpenLayers 内部在解析要素的同时自动将经纬度转换为目标视图投影（EPSG:3857），开发者无需手动编写遍历转换逻辑。

2. 源码与关键 API 剖析

  • new VectorSource({ url: '...', format: new KML() })：声明异步加载并解析 KML 文件。
  • map.forEachFeatureAtPixel(pixel, callback)：基于离屏命中检测（Hit-Detection）Canvas 快速检索光标下的要素集合。
  • map.getTargetElement().style.cursor = 'pointer'：交互状态反馈。

3. 生产实践踩坑与性能调优

  • 样式提取与 GC 内存开销： KML 解析器默认 extractStyles: true。若 KML 包含上万个独立样式节点，会导致创建上万个 ol/style/Style 实例引发内存飙升。 生产中若不需要内嵌样式，建议显式设置 new KML({ extractStyles: false }) 并通过统一的图层 style 函数进行批量渲染。
