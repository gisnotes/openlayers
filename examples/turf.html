Example showing the integration of turf.js with OpenLayers. The turf.js function along is used to display a marker every 200 meters along a street.

此示例演示了在 OpenLayers 中集成现代化的地理空间分析库 Turf.js。 系统使用 Turf.js 的 length 函数计算街道折线的实际物理总长度，并调用 along 函数沿该道路线段每隔 200 米（0.2 公里）精确计算并放置一个里程桩标记要素。

📚 学习记录与技术深度解读

1. 核心架构与设计思想

  • Turf.js 模块化空间分析架构： Turf.js 是现代 Web 开发中最流行的“云原生/前端轻量级空间分析引擎”。它完全基于标准 GeoJSON（RFC 7946）数据结构，无需加载笨重的 C++ 编译底座，支持按需引入模块（如 @turf/along、@turf/length）。
  • GeoJSON 标准总线作为对象互操作桥梁： OpenLayers 与 Turf.js 之间通过内存级 GeoJSON 进行无缝数据交换： 1. format.writeFeatureObject(feature)：以零网络开销将 OpenLayers 内存要素转为标准的纯 JavaScript GeoJSON 字典对象送入 Turf； 2. Turf 内部基于球面大地测量学（WGS84 半正矢方程）执行高精度的 length（总测地长）与 along（沿线定长取点）； 3. format.readFeature(turfPoint)：将 Turf 输出的 GeoJSON 点转回 OpenLayers 要素，执行坐标转换后批量渲染。

2. 源码与关键 API 剖析

  • length(turfLine, { units: 'kilometers' })：计算折线的真实大地测地物理长度（单位：千米）。
  • along(turfLine, distance, { units: 'kilometers' })：沿指定线段路径测量距离，精准返回对应的经纬度航点（Point）。
  • marker.getGeometry().transform('EPSG:4326', 'EPSG:3857')：将大地测量点重投影至墨卡托视图空间。

3. 生产实践踩坑与性能调优

  • Turf.js 严苛的坐标系要求（必须为 EPSG:4326 经纬度）： Turf.js 的测地线几何运算库在底层假定坐标为 WGS84 经度与纬度（度数）。 如果错误地将已经转换为 EPSG:3857（以米为单位，数值动辄数百万）的 GeoJSON 传给 Turf，算法内部会由于度数严重溢出产生不可逆的计算错误。 规范流程：保持原始数据为 EPSG:4326 $\to$ 传入 Turf 分析 $\to$ 将结果 transform('EPSG:4326', 'EPSG:3857') 上屏渲染。
