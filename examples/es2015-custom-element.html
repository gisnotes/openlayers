The example creates and registers a custom element, ol-map, which contains a simple map. Note: Only works in browsers that supports ShadowRoot.

本示例创建并注册了一个符合 W3C Web Components 标准的原生自定义元素 <ol-map>，其内部封装了一个完整的 OpenLayers 地图实例。注意：该特性依赖支持 ShadowRoot（影子根节点）的现代浏览器。

📚 学习记录与技术深度解读

1. 核心架构与设计思想

  • 框架无关的原生组件化（Framework-Agnostic Web Components）： 在微前端、多技术栈并存（React / Vue / Angular / Svelte / 原生 HTML）的大型企业系统中，将复杂地图封装为原生 Custom Element，无需依赖任何第三方框架运行时，即可像使用 <video>、<canvas> 一样在任意页面中声明式引入。
  • Shadow DOM 样式强力隔离（CSS Encapsulation）： 传统 OpenLayers 开发中，全局 CSS（如 Bootstrap、Tailwind、Ant Design 等）经常意外覆盖 OpenLayers 原生控件（.ol-control、.ol-viewport）的定位和盒模型。通过 attachShadow({ mode: 'open' }) 创建独立的 Shadow DOM 边界，外部样式的任何规则均无法穿透渗透，地图内部样式也不会污染外部页面。

2. 源码与关键 API 剖析

  • class OLComponent extends HTMLElement：标准 ES6 原生类继承，直接继承 DOM 节点的所有基础事件与属性体系。
  • :host { display: block; }：在 Shadow DOM 的内置样式中至关重要。自定义 HTML 标签默认属于 display: inline，若不显式声明为块级元素，设置 width: 100%; height: 100% 将完全失效，导致地图无法撑开。
  • link.setAttribute('href', 'theme/ol.css')：由于 Shadow DOM 的隔离性，宿主外层引入的 ol.css 无法生效，必须在 ShadowRoot 内部显式引入 OpenLayers 核心样式文件。
  • customElements.define('ol-map', OLComponent)：W3C 规范要求自定义元素名称必须包含至少一个连字符（短横线 -），以与未来的标准 HTML 原生标签区分。

3. 生产实践踩坑与性能调优

  • 组件卸载与内存泄漏防护： 示例直接在 constructor 中初始化地图。在复杂的单页应用（SPA）中，组件被反复挂载与移除，必须在 disconnectedCallback() 生命周期钩子中显式调用 this.map.setTarget(null) 并注销事件监听器，避免未释放的闭包导致巨大的内存泄漏。
  • 异步渲染与容器尺寸探测（Resize）： 若 <ol-map> 在 DOM 渲染树尚未完成布局（宽高为 0）时就实例化地图，会导致地图瓦片无法加载或视口扭曲。生产环境应在 connectedCallback() 中结合 ResizeObserver，在容器获得真实像素尺寸后触发 this.map.updateSize()。
  • 数据绑定与属性监听（observedAttributes）： 可实现 observedAttributes 静态属性，监听 zoom、center 等 HTML 标签属性的变更，在 attributeChangedCallback() 中自动同步驱动视图更新。
