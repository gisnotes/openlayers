本示例演示如何直接在 WGS84 地理坐标系（EPSG:4326）下加载来自 MapTiler 的矢量切片，并借助 ol-mapbox-style 库将 Mapbox Style JSON 样式表动态解析并应用到 OpenLayers 矢量切片图层中。

**提示**：在实际项目中使用本示例时，请务必前往 https://www.maptiler.com/cloud/ 申请并配置您专属的 API Key。若 API Key 过期或无效，底图将无法加载显示。

--- ### 📚 学习记录与技术深度解读 (Learning Notes) #### 1. 核心架构与设计思想 (Core Architecture & Design) - **打破 Web 墨卡托（EPSG:3857）的固有垄断**： 市面上绝大多数矢量切片遵循 Mapbox 矢量切片标准（基于 EPSG:3857）。但很多专业行业（航海、航空、极地科考、气象遥感）原生数据以等经纬度网格（EPSG:4326）存储。OpenLayers 具备业界最强大的投影内核，允许 `VectorTileSource` 直接配置 `projection: 'EPSG:4326'`，无需中间坐标重投影即可直接消费服务端的经纬度瓦片。 - **ol-mapbox-style 样式引擎适配**： Mapbox Style 规范原生是针对 Mapbox GL 编写的，而 `ol-mapbox-style` 作为桥接器，将 Mapbox JSON 样式的 Filter、Paint、Layout 属性实时转换为 OpenLayers 的 `Style`、`Text`、`Fill`、`Stroke` 渲染指令。在非 3857 投影中，需显式传入 `resolutions`，确保样式中的缩放级别（Zoom-and-Function）与自定义切片网格完美对齐。 #### 2. 源码与关键 API 剖析 (Source Code & API Analysis) - `createXYZ({ extent, tileSize, maxResolution, maxZoom })`： 在 WGS84 坐标系下，全球经度范围为 `[-180, 180]`（宽度 360°），纬度范围为 `[-90, 90]`（高度 180°）。当切片大小为 `512` 像素且 Zoom 0 全球分为两张切片时，其最大分辨率 `maxResolution = 180 / 512 = 0.3515625 度/像素`。通过精确配置 TileGrid 参数，客户端发起的瓦片计算能 100% 契合服务端切片矩阵金字塔。 - `applyStyle(layer, url, { resolutions })` 与 `applyBackground(layer, url)`： - `applyStyle`：异步下载 Mapbox Style JSON，递归构建图层图元样式函数，并绑定到 `layer` 上。 - `applyBackground`：提取样式表中的 `background` 层颜色，将其应用为底层背景，防止瓦片透明区域露出默认白色底色。 #### 3. 生产实践踩坑与性能调优 (Production Pitfalls & Optimization) - **4326 切片的长宽比陷阱**： Web 墨卡托是 1:1 的正方形（全球范围为 1 个切片，Zoom 0 是 $1 \times 1$），而 EPSG:4326 全球范围是 2:1 的长方形。如果瓦片使用 $512 \times 512$ 像素，Zoom 0 通常由 $2 \times 1$ 两张切片组成（X 轴两张，Y 轴一张）。若未正确设置 `maxResolution` 或 `extent`，切片行号和列号计算将错位，导致地图错乱或大面积 404。 - **字体与雪碧图（Sprites）跨域加载**： Mapbox 样式通常依赖 Glyph 字体 PBF 和 Sprite 图标图集。在企业内网部署 EPSG:4326 矢量切片服务时，除 Style JSON 外，必须确保字体和雪碧图服务也具备跨域 CORS 头（`Access-Control-Allow-Origin: *`）。 tags: "vector tiles, epsg4326, mapbox style, ol-mapbox-style, maptiler, grid" ---
