Layer rendering can be manipulated in prerender and postrender event listeners. These listeners get an event with a reference to the Canvas rendering context. In this example, the postrender listener applies a filter to the image data.

图层的渲染管线可通过 prerender 和 postrender 事件监听器进行拦截和后处理。这些事件对象中挂载了当前图层的 Canvas 2D 绘图上下文（event.context）。本示例中，通过在 postrender 监听器中获取视口像素数据并应用自定义 3×3 卷积核（Convolution Kernel），实现了锐化、模糊、浮雕、投影和边缘检测等图像后处理特效。

--- ### 📚 学习记录与技术深度解读 (Learning Notes) #### 1. 渲染事件拦截与 Canvas 上下文 (Render Hooks & Canvas Context) - **后处理拦截机制**: 当切片图层触发 `postrender` 事件时，当前视口范围内的切片已全部光栅化绘制到图层独享或共享的 HTML5 Canvas 画布上。此时挂载于事件参数中的 `event.context` 允许开发者直接调用原生 2D Canvas 上下文方法。 - **像素级数据读写**: 通过 `context.getImageData(0, 0, width, height)` 可以提取视口当前帧的 RGBA 原始字节流（`Uint8ClampedArray`），并在经过数学变换后通过 `context.putImageData(output, 0, 0)` 将新像素阵列写回，实现任意基于 CPU 的着色器后处理效果。 #### 2. 图像空间卷积核与亮度归一化原理 (Convolution & Normalization) - **二维卷积数学模型**: 卷积滤波将目标像素周围 $3 \times 3$ 邻域内的各点颜色通道与预设矩阵（Kernel）相乘并累加： $$I_{\text{out}}(x, y) = \sum_{j=-1}^{1} \sum_{i=-1}^{1} I_{\text{in}}(x + i, y + j) \cdot K(i + 1, j + 1)$$ - **权重归一化 (Kernel Normalization)**: 当卷积核中各权值之和大于 0 时（如模糊滤波 $\sum K = 9$），必须将所有权重除以该总和（每个权重为 $1/9$），以确保滤波后的画面整体能量守恒（即总亮度不发生漂移）；对于差分求导类算子（如边缘检测核 $\sum K = 0$），则无需除以总和，且 Alpha 通道强制设置为 255 保证完全不透明。 #### 3. 生产实践陷阱与避坑指南 (Production Pitfalls & Best Practices) - **CPU 计算瓶颈与 GPU 着色器选型**: `getImageData()` 与纯 JS 的双重像素循环在常规 1080P/2K/4K 屏幕上计算量巨大（通常需数十毫秒），会导致地图拖拽漫游时出现严重掉帧。生产环境中若需全局图像后处理，首选 OpenLayers 的 `WebGLTile` 搭配自定义片元着色器（Fragment Shader），将矩阵卷积计算交给 GPU 硬件多核心并行管线处理。 - **跨域画布污染 (CORS Taint)**: 若切片源服务器未在 HTTP 响应头中正确下发 `Access-Control-Allow-Origin: *`，浏览器会标记 Canvas 为被污染状态，调用 `getImageData()` 将直接抛出 `SecurityError` 安全异常。在配置图层源时务必确保切片支持 CORS。 - **边界箝位与越界保护 (Clamp to Edge)**: 视口外边缘像素缺少相邻采样点，代码采用 `Math.min(maxCoord, Math.max(0, currentCoord))` 实施边缘箝位采样，防止数组越界计算产生黑边或内存访问错误。 tags: "filter, image manipulation, maptiler" ---
