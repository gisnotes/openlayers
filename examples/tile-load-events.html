--- layout: example.html title: Tile Load Events / 瓦片加载事件与精细进度监控 shortdesc: Example using tile load events. / 演示如何监听 ImageTile 瓦片加载生命周期事件并构建高精度的动态加载进度条。 docs: | Image tile sources fire events related to tile loading. You can listen for tileloadstart, tileloadend, and tileloaderror type events to monitor tile loading progress. This example registers listeners for these events and renders a tile loading progress bar at the bottom of the map. The progress bar is shown and hidden according to the map's loadstart and loadend events. 切片栅格数据源（如 ImageTile、XYZ、TileWMS 等）在网格瓦片拉取时会触发细粒度生命周期事件。你可以通过监听 tileloadstart、tileloadend 以及 tileloaderror 事件，精确量化瓦片请求池的队列状态与下载完成比率。 本示例在地图视口底部渲染了一个响应式进度条，将各个瓦片的加载推进过程转化为平滑的百分比宽度增长；同时利用地图实例的 loadstart 与 loadend 事件管理进度条的生命周期显隐与复位。 --- ### 📚 学习记录与技术深度解读 (Learning Notes) #### 1. 核心架构与设计机制 (Core Architecture & Mechanics) - **瓦片池状态机模型（Tile Pool State Machine）**： 地图在一次漫游缩放中会计算出当前视口需要的若干瓦片索引 (z, x, y)。OpenLayers 内部通过 TileQueue 进行优先级调度（按距离视口中心的距离从近到远排序）： - 队列触发网络请求时，数据源抛出 tileloadstart； - 单张瓦片 Image 元素接收到 load 回调并完成纹理上传时，抛出 tileloadend； - 若瓦片返回 404、500 或因网络断开触发 error，抛出 tileloaderror。 - **累积比率进度计算法（Cumulative Ratio Progress）**： 与单张图像的 0/1 状态不同，视口涉及大量瓦片。进度条采用 (loaded / loading) * 100 的动态累积法，当视口持续滚动时，loading 计数动态上扬，loaded 计数平稳追赶，确保进度条能真实反映并发流式加载全貌。 #### 2. 关键代码解析与 API 模式 (Code Deep Dive & API Patterns) - **多事件监听合并与容错闭合**： ```javascript source.on('tileloadstart', function () { progress.addLoading(); // loading++ 并重绘宽度 }); // 使用数组同时捕获成功和失败，保证 loaded 计数器绝对自闭合 source.on(['tileloadend', 'tileloaderror'], function () { progress.addLoaded(); // loaded++ 并重绘宽度 }); ``` 严禁只监听 tileloadend 而忽略 tileloaderror，否则一旦发生少量瓦片 404，loaded 将永远小于 loading，导致进度条停滞在 90%+ 且无法复位。 - **重置与延迟消隐机制**： ```javascript Progress.prototype.hide = function () { const style = this.el.style; setTimeout(function () { style.visibility = 'hidden'; style.width = '0px'; }, 250); }; ``` 延迟 250ms 可使 CSS transition: width 250ms ease 完整跑完最后的满格动画，随即将宽度复位为 0，防止下一次加载时出现反向缩回的视觉瑕疵。 #### 3. 工程避坑与高可用实践 (Production Pitfalls & Best Practices) - **计数器数值膨胀与归零重置**： 在长时间运行的监控看板或大屏系统中，如果用户持续漫游，loading 和 loaded 计数器会持续单调递增至数万。建议在 loadend 触发且进度条隐藏后，将 this.loading = 0; this.loaded = 0; 彻底复位归零，避免数值精度漂移与潜在逻辑溢出。 - **跨瓦片源并发混淆隔离**： 若地图挂载了多个图层（例如基础底图 + 专题注记 + 业务图斑），建议为每个关键图层单独实例化独立的 Progress 监控，或者在全局状态机中针对每个源计算带权重的综合进度，避免单个迟钝的影像图层拖垮整张地图的交互就绪指示。 tags: "tile, events, loading" ---
