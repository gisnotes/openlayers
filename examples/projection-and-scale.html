const newMPU = newProjection.getMetersPerUnit(); ``` 2. **计算指定点处的真实地表点分辨率系数**： 传入 `1 / MPU` 计算单位标称分辨率在当前位置对应的地表真实米数： ```javascript const currentPointResolution = getPointResolution(currentProjection, 1 / currentMPU, currentCenter, 'm') * currentMPU; const newPointResolution = getPointResolution(newProjection, 1 / newMPU, newCenter, 'm') * newMPU; ``` 3. **推导新标称分辨率**： 由于当前屏幕中心点的真实地表物理分辨率为： $$R_{\text{ground}} = R_{\text{current}} \times \text{currentPointResolution}$$ 若要使目标投影在屏幕上呈现相同的地面物理比例尺，新标称分辨率应满足： $$R_{\text{new}} \times \text{newPointResolution} = R_{\text{current}} \times \text{currentPointResolution}$$ 由此推导出计算公式： $$R_{\text{new}} = \frac{R_{\text{current}} \times \text{currentPointResolution}}{\text{newPointResolution}}$$ #### 3. 控件联动：ScaleLine（比例尺控件）的高级参数 示例中挂载了专业的条形比例尺控件： ```javascript const scaleControl = new ScaleLine({ units: 'metric', // 公制单位 (m / km) bar: true, // 启用带分段刻度的标尺条外观 steps: 4, // 划分为 4 个主要刻度区间 text: true, // 在刻度上方直观显示距离文本 minWidth: 140, // 控件最小宽度 (px) }); ``` 在切换投影时仔细观察左下角的比例尺： * 无论是从 WGS 84（经纬度度数）切到 Web 墨卡托（米制投影），还是反向切换； * 比例尺上显示的物理像素宽度与实际地理公里数均严密保持一致，证明视口地表比例尺实现了平滑无损过渡。 #### 4. 技术方案对比 | 切换策略 | 实现代码 | 视觉与测量表现 | 适用场景 | | :--- | :--- | :--- | :--- | | **直接复用 Zoom** | `new View({ zoom: oldView.getZoom(), ... })` | 比例尺剧烈跳变；度数与米制缩放级别无法对齐；高纬度失真严重 | 粗略定位，对比例精度无要求的场景 | | **直接复用 Resolution** | `new View({ resolution: oldView.getResolution(), ... })` | 灾难性形变（度与米相差五到六个数量级，整图全黑或瞬间飞出地球） | 严禁跨单位使用 | | **`getPointResolution` 动态换算（本示例）** | `newResolution = (currRes * currPointRes) / newPointRes` | **完美保持地表真实比例尺**；严谨抵消单位差异与纬度投影变形 | 专业 GIS、精准量测、多坐标系切换标准实现 | tags: "projection, scale" ---
