High DPI WMTS / 高分辨率 WMTS 服务 (HiDPI)

hidpi4 retina3 wmts7

Example of a WMTS based HiDPI layer. / 基于 WMTS 规范的高分视网膜瓦片图层加载与像素比动态自适应示例。

The WMTS source has a `tilePixelRatio` option. A HiDPI capable WMTS could provide tiles with 512x512 pixel tiles, but use them in a 256x256 pixel tile grid. In this case `tilePixelRatio` needs to be set to `2`.

OpenLayers 的 WMTS 数据源提供了 tilePixelRatio 选项。支持 HiDPI（高分辨率）的 WMTS 服务可以提供 512×512 物理像素的瓦片，但将其安置在 256×256 逻辑像素的标准切片网格中。在这种情况下，只需将 tilePixelRatio 显式指定为 2 即可实现高清自适应渲染。

📚 学习记录与技术深度解读

1. 核心架构与设计思想

  • OGC WMTS 规范与高分切片的冲突与调和： 传统 OGC WMTS 规范假定切片矩阵（TileMatrixSet）的标准像素大小为 0.28mm（约 90.7 DPI），切片尺寸多为 256×256。当高清设备普及后，服务端有两种扩展方式：一是提供更深层级的切片，但会导致注记字体缩水微小无法阅读；二是保持地理网格比例尺不变，将瓦片图像的像素密度提升为 512×512（2× HiDPI），并在元数据中提供专属高清图层（如奥地利国家地图 bmaphidpi）。
  • 端侧动态自适应机制（Adaptive Pixel Ratio）： 本示例通过 OpenLayers 内置常量 DEVICE_PIXEL_RATIO 实时探测用户的显示环境。在普通显示器（DPR = 1）上请求常规 geolandbasemap 图层以节省带宽；在视网膜屏幕（DPR > 1）上无缝切换为 bmaphidpi 高分图层并配置 tilePixelRatio: 2，达到最佳视觉清晰度与加载性能的平衡。

2. 源码与关键 API 剖析

  • DEVICE_PIXEL_RATIO：封装了 window.devicePixelRatio || 1，安全处理不同宿主环境与旧版浏览器的兼容性。
  • WMTSCapabilities().read(xmlText)：OpenLayers 的 XML 自动化反序列化解析器，能从复杂的 OGC XML 中提取图层标识、切片格式、坐标系、边界范围及切片矩阵列表。
  • optionsFromCapabilities(capabilities, config)：便捷提取工具，快速从 Capabilities 对象中筛选出指定 layer（图层名）与 matrixSet（切片矩阵集）对应的构造参数。
  • options.tilePixelRatio = 2：核心参数，通知 OpenLayers 当前瓦片图片应按照 1 / tilePixelRatio（即 0.5 倍）缩小排布在逻辑网格上，确保几何坐标与高分辨率切片严丝合缝。

3. 生产实践踩坑与性能调优

  • GetCapabilities 元数据高频请求隐患： WMTS Capabilities XML 文本通常长达数十甚至数百 KB。每次前端初始化都通过 fetch() 动态拉取会严重影响首屏加载速度。生产环境推荐在编译期（Build Time）或服务端网关层预先将 Capabilities 结果缓存转为 JSON，直接传入配置对象。
  • 双屏跨越（DPR 切换）陷阱： 当用户将浏览器窗口从 Retina 笔记本屏幕拖拽到外接普通 1080P 显示器时，window.devicePixelRatio 会发生跃迁。若需极致体验，可监听 window.matchMedia('(resolution: ...)') 变化，在跨屏时动态重建瓦片数据源。
  • TileMatrix 标识符对齐： 不同 GIS 商业软件发布的 WMTS 切片矩阵 ID 各异（有的为 0, 1, 2...，有的为 google3857:0, google3857:1...）。使用 optionsFromCapabilities 时务必确认 matrixSet 属性与服务端元数据完全一致。
main.js 
import Map from 'ol/Map.js';
import View from 'ol/View.js';
import WMTSCapabilities from 'ol/format/WMTSCapabilities.js';
import {DEVICE_PIXEL_RATIO} from 'ol/has.js';
import TileLayer from 'ol/layer/Tile.js';
import WMTS, {optionsFromCapabilities} from 'ol/source/WMTS.js';

const capabilitiesUrl =
  'https://mapsneu.wien.gv.at/basemapneu/1.0.0/WMTSCapabilities.xml';

// HiDPI support:
// * Use 'bmaphidpi' layer (pixel ratio 2) for device pixel ratio > 1
// * Use 'geolandbasemap' layer (pixel ratio 1) for device pixel ratio == 1
// 高分辨率（HiDPI）支持：
// * 设备像素比 > 1 时使用 'bmaphidpi' 高清图层（像素比为 2）
// * 设备像素比 == 1 时使用 'geolandbasemap' 常规图层（像素比为 1）
const hiDPI = DEVICE_PIXEL_RATIO > 1;
const layer = hiDPI ? 'bmaphidpi' : 'geolandbasemap';
const tilePixelRatio = hiDPI ? 2 : 1;

// Initialize map view
// 初始化地图视图
const map = new Map({
  target: 'map',
  view: new View({
    center: [1823849, 6143760],
    zoom: 11,
  }),
});

// Fetch and parse WMTS Capabilities XML
// 请求并解析 WMTS Capabilities 元数据 XML
fetch(capabilitiesUrl)
  .then(function (response) {
    return response.text();
  })
  .then(function (text) {
    const result = new WMTSCapabilities().read(text);
    const options = optionsFromCapabilities(result, {
      layer: layer,
      matrixSet: 'google3857',
      style: 'normal',
    });
    options.tilePixelRatio = tilePixelRatio;
    options.attributions =
      'Grundkarte: <a target="_blank" href="https://basemap.at/">basemap.at</a>';
    map.addLayer(
      new TileLayer({
        source: new WMTS(options),
      }),
    );
  });
